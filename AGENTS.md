# Coding rules

1. Do not reorganize the folder structure unless explicitly asked.
2. Do not rewrite working components unnecessarily.
3. Do not install packages unless genuinely required.
4. Use the existing stack.
5. Use plain CSS unless explicitly changed.
6. Preserve existing functionality when adding features.
7. Make the smallest reasonable change for each task.
8. Do not create duplicate components or systems.
9. Do not replace working architecture without explaining why first.
10. Before major architectural changes, explain the proposed change.
11. Do not modify unrelated files.
12. After completing a task, report files changed, what changed, and anything needing testing.
13. Never assume a feature is complete just because the UI exists.
14. Prefer real functionality over fake demo interactions for production features.
15. Keep the MVP focused.
16. Only one coding agent should modify the project at a time.
17. The repository and these Markdown files are the source of truth.
18. Do not silently change product direction.
19. Do not add features merely because they are technically interesting.
20. Optimize for shipping a convincing business outcome.
